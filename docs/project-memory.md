## 当前事实

- MT4 原生 `OBJ_RECTANGLE_LABEL / OBJ_BUTTON / OBJ_EDIT` 无圆角属性；正式 `v31.01` 即使使用平面边框，实机仍无法达到 HTML 的圆角卡片质感。当前验证路线是独立 `CCanvas` 演示，满意后再单独设计正式产品迁移。
- `canvas-panel-demo-v1` 实机已确认 Canvas 圆角路线可行，但排版仍有字号偏大、卡片纵向密度不均、右侧辅助文字对不齐和七条日志拥挤的问题。
- `canvas-panel-demo-v2` 保持单 `CCanvas`、固定 `550 x 1150px` 和 UI-only 安全边界；使用 `0.75` 的 px-to-point 换算、固定六卡片纵向栅格、实际文字宽度右对齐，以及 `214px` 独立日志卡片。它不读取订单、不调用交易 API，也不修改正式 `v31.01`。
- `canvas-panel-demo-v3` 根据 v2 实机截图做局部收尾：标题拆为固定的产品名、`V31.01` 和运行状态槽位；“当前选择”加高；后续卡片采用 `8px` 节奏；日志高 `204px` 并与面板底边留 `10px`；四个信息蓝控件使用较柔和的 `#497EDE` 和白字。以后正式显示版本统一使用 `Vxy.mn`。
- v22-v23 建立普通/双向突破 8 档阶梯状态机和持久化：按 ticket 保存原始手数、触及/完成档位及显示编号；只有 broker comment 明确关联 old/new ticket 时迁移，避免串单。
- v30.07 起，broker comment 明确关联 old/new ticket 的手动或外部部分平仓可迁移完整阶梯状态，不再要求旧状态处于“EA 正在等待自己部分平仓”的内部标记。迁移保留原始手数、8 档已触及/已完成状态、显示编号、普通所有权和组合成员身份；没有明确 lineage 时暂停接管该疑似后继票，不猜测迁移，也不按新订单重开阶梯。v30.09 已把普通票的严格 lineage 恢复前置到 `IsNormalManagedOrder()` 过滤之前。

- v24-v28 依次完成手动下一阶、手动 SL/追踪切换、按钮重排和阶梯/订单标签视觉调整。手动下一阶成功写入 `levelDone` 并立即移除已完成档位显示。

- v30 新增 UI 要求：多笔订单同时显示阶梯时，阶梯文字必须小于现有 9 号字，并修复文字横向漂移、侵入 K 线和底部面板遮挡。v29.1 当前通过 `OBJ_TEXT + datetime` 及 `0.98/0.82/0.66` 三个横向时间槽定位，受图表右移、缩放和未来空白影响；v30 设计不得继续依赖该时间比例作为最终标签布局。
- 阶梯文字允许轻微垂直重叠：两个文字框的垂直重叠高度不超过单行文字高度的 `30%` 时保持原位；只有超过 `30%` 才把冲突标签分配到相邻横向列。不得通过上下移动文字解决冲突，标签纵坐标始终对应其真实阶梯价格线。
- 阶梯标签默认字号为 `8`，正式新操作面板提供字号可调设置。所有标签优先使用图表右侧主列；同列重叠超过 `30%` 时依次向左分配第二、第三及后续像素列。没有超限冲突的标签可共用主列，不按订单永久占列。
- 组合归零价按 broker `MODE_TICKSIZE` 的最近有效价格标准四舍五入，不按 BUY 向上/SELL 向下定向规整，也不额外增加安全 tick。价格规整误差最多为半个 tick；规整后重新计算并记录预计净结果，但接受由该四舍五入造成的正负残差。归零方程无解、剩余有效权重为零或关键 tick 数据无效时仍拒绝启动，提示 `无法计算有效归零价`，不得修改 TP/SL。
- 同价或近价的多张未管理订单各自保留独立可点击的 `未管理` 标签，内部绑定精确 ticket；图表不显示 ticket 或数量。标签发生超限重叠时使用稳定像素横向错列。点击后仅高亮所选标签，正式面板显示 ticket、方向、当前手数、开仓价、Magic、当前 SL/TP；再点击 `加入管理` 才执行。执行前重新核验该快照，订单关闭或关键状态变化时取消本次操作并给出非阻断提示。
