# 项目记忆（MT5 自动保本）

## 产品与基线
- MT5 EA「自动保本」，含「双向突破」模块；是 MT4 v31.02 交易引擎的 MQL5 原生重写。
- 当前已验收实盘基线：v32.16（git tag `v32.16`）。
- MT4 已冻结，只留 `src/mt4/自动保本_v31.02.mq4` 作历史参照，不再开发。
- 只支持 Hedging 账户；代码禁止任何账户模式判断（如 `ACCOUNT_MARGIN_MODE`）。

## 仓库、版本与部署
- 单一源码树：`src/mt5/AutoBreakeven.mq5` + `src/mt5/include/*.mqh` + `src/mt5/resources/fonts/Inter-*.ttf`。
- 版本号唯一来源 `#define AB_EA_VERSION`，每轮交付递增。
- 旧版本靠 git tag 保留，不再按版本复制源码。候选在以版本号命名的分支开发，用户实盘验收后合并 `main` 并打 tag。
- 部署：每个版本单独放实盘终端 `MQL5\Experts\AutoBreakeven_v32_xx\`，用户自选版本挂载；不动正在运行的版本，不替用户切图表或重启终端。

## 验证
- 编译以 MetaEditor 日志 `0 errors, 0 warnings` 为准。
- `tests/mt5/` Python 合同测试读当前源码树；`tests/mt5/tester/` 脚本（v32.06 起，每个一份同名 ini）在 `.tester-terminal\` 跑数学模式（`Model=3`），交易函数被模拟，测不出真实异步回报乱序。
- 测试 ini 必须带 `[Common] Login/Server` 和 `[Tester] Login`，CRLF 换行；不要用 `Model=4`（真实 tick 要登录券商，便携终端报 `account is not specified`）。
- 主 EA 必须放在某个终端的 `MQL5\Experts\` 下编译，否则字体 `#resource` 路径无效。
- Python/编译/Tester 通过都不算实盘验证，实盘验收只由用户完成。
- 查实盘问题先要 `AB_DIAG` 日志、ticket、截图；线画对不代表执行链对。

## 开发约束
- 只实现用户批准的行为；新想法先记待确认，不顺手加功能、参数、保护分支或改优先级。
- 面板只经 `ExecuteCommand(...)` 发意图、`GetEngineSnapshot()` 读快照，不自己算交易数值。
- 受管对象用稳定 `ManagedEntityId`，血缘用 `POSITION_IDENTIFIER`，ticket 只是当前引用；图表对象不是状态来源。

## 单位与规整
- 1 微点 = `SYMBOL_POINT`；微点参数 = 参数 × `SYMBOL_POINT`，不做位数倍率换算。TickSize 只用于价格合法化。
- 止损价按 TickSize 规整，远离现价（BUY 向下、SELL 向上），已在 tick 上的不动（黄金 TickSize = Point，实际不变）。突破挂单价不规整。
- 手数按 `SYMBOL_VOLUME_STEP` 向下取整，不因最小手数放大；低于最小手数或留下非法余仓即不可执行。

## 订单管理范围
- 普通单默认只管 `Normal_Managed_Magic=0`（`-1`=全部非突破单），`CurrentSymbolOnly` 默认只管当前品种。突破 Magic（默认 8888）不走普通通道、不进组合，面板普通命令不作用于它。
- EA 启动前已有的仓位不自动接管，启动后新开的自动登记。例外：本地无状态文件时按当前真实持仓全部重建，所以别随意删状态文件（会丢失已完成档位）。
- 加入管理：点 `未管理` 标签选中当前品种非突破持仓再加入，原始仓位 = 当时手数。退出管理：停止管理、移出组合、保留 SL/TP、不平仓。
- 图表单选，不持久化。没选中时，手动命令和面板显示都作用于当前品种开仓最晚的受管普通仓位（按 `POSITION_TIME_MSC`）。

## 阶梯止盈（普通、突破各 L1–L10）
- 每档 = 距离（微点）+ 原始仓位比例；任一为 0 即关闭，中间档可关，L9/L10 默认关。
- 手数不可执行时只标「手数不足、不可执行」：不发单、不算完成、不改全平，后续档照常。
- 触发侧 BUY 看 Bid、SELL 看 Ask；SELL 图线随实时点差换成 Bid 等效价。
- 只在当前价仍满足档位时发单/重试；触及未成交不锁存，回撤暂停、不追平，再触及再试。
- 只有 Deal 证明成交量完成才标完成；结果未知先查历史，不重复发。普通阶梯每仓位最多一个在途请求。
- 面板「阶梯止盈」是运行时开关（挂载默认开），关闭时跳过整个普通阶梯阶段，含普通组合成员。
- 「触发下一阶止盈」：按 L1→L10 取第一个启用、未完成、无在途的档，立即平该档手数，不看价格。

## 自动保本与手动 SL
- 到达「自动保本触发距离」后设 SL：M1 极值（开仓那根 M1 的 BUY 最低/SELL 最高，加偏移）或开仓价加偏移；只收紧不放松。
- 面板「自动管理」三档 M1 极值止损 / 开仓价止损 / 关闭 是运行时控制；启动默认由 `Normal_Use_M1_Mode` 决定，不改写输入面板。
- 用 `CopyTicksRange` 回放上次以来的全部 tick 判断触发，防漏；触发后锁存，等目标 SL 可用再发。
- 只认自己登记的 operation 回报才算完成；在途超 30 秒未确认就清除重试。组合 SL 接管时普通自动保本暂停。
- 手动 M1 / 开仓价 / 四档追踪（默认 50/100/200/300 微点）可反复点、任意切换，每次按当时行情重算。
- 追踪止损至少前进 `Normal_Trail_Min_Step_MicroPoints`（默认 5 微点，0 = 每次都移）才改；多个追踪仓位轮流发，避免限速时总轮不到后面的单。
- 「停止追踪」：停止移动、保留当时 SL，自动保本不再改写，直到用户再点 M1/开仓价/追踪档；阶梯不受影响。

## 手动平仓
- 四档比例（默认 5/10/25/50%，按原始仓位）+ 整单平仓；向下取整，盈亏都可平，不改阶梯状态。

## 组合保本
- 按钮：多单/空单组合保本挂TP、多单/空单无阶梯组合保本、取消组合保本止盈；多空独立。成员 = 当前品种同方向受管普通持仓，建立后新仓不加入。
- 点击时冻结成员、手数、开仓价、已记录的 Profit+Swap+Commission（不估未来费用/滑点，无缓冲）和报价数据。普通组合模拟成员未完成的 L1–L10。
- 归零价按 TickSize 提前规整：多单向下、空单向上；多单看 Bid、空单看 Ask，空单图线为冻结点差下的 Bid 等效价。净值已 ≥0 直接进入退出；数据无效或无解则拒绝，不动 TP/SL。
- 退出模式三选一（输入默认保本 TP，面板可切，建立时冻结；改模式要重新点组合按钮走热切换）：
  - 保本 TP：成员 TP = 归零价；部分成功不回滚，失败的重试；价格已到而 TP 没装上的市价平。
  - 追踪止损：首次到归零价才从 ACTIVE 进 EXITING 并用当时真实价初始化极值，之前不追踪不平仓。平仓失败时只要价格仍在虚拟退出线不利一侧就持续重试，回安全侧暂停（与阶梯规则不同）。
  - 单次保本 SL：到归零价后给成员装一次保本 SL（已有同等或更好 SL 即满足）；未全部装上且价格反向达到「反向强平距离」就强平原组合全部存续成员，直到全关或用户取消；依据持久化的 EXITING 阶段判断。
- 追踪距离、反向强平距离（默认 100 微点）只来自 EA 输入。
- 取消：只清 EA 设置且仍等于记录值的 TP，人工改过的保留；不恢复建组合前的 SL/TP；回到普通 SL 与阶梯管理；可中止未完成的强平。
- 热切换：先存新快照，再清旧组合 TP，清完才激活，中途失败可恢复。
- 用户对某成员点 M1/开仓价/追踪/停止追踪后，该成员在当前组合代次内脱离组合 SL；新代次可重新接管。
- 成员退出或被外部平掉只移除该成员，不重算归零价。
- 无阶梯组合：成员不锁存、不执行阶梯，未成交触及/待重试清除，已完成档保留；取消后只按当刻价格重判，不补做；图上隐藏成员 L1–L10，保留开仓标注。

## 双向突破
- 只由「启动突破」触发；独立 Magic、手数、挂单距离、初始 SL、锁损距离和 L1–L10。
- Buy Stop = Ask + 距离，Sell Stop = Bid − 距离，不做方向取整；券商不接受就拒绝本次，不偷改距离。一边失败即回滚撤另一边。
- 一边成交后 OCO 撤对侧；只在真实突破持仓存在时执行，只删 Stop/Limit 挂单。
- 历史已终结、无真实挂单、无真实持仓、无在途操作时进入 DONE 并清理，可再启动；仍有真实挂单或持仓则拒绝新周期。
- 突破阶梯到价即发，不等改 SL 的服务器确认（用户在 v32.16 提出并验收：快速行情里改 SL 回报慢，旧版死等会错过止盈）；改 SL 照常先发、不重复发。同一 tick 里阶梯正在平仓时，该仓位暂不新发 SL，等平仓有结果再补。锁损（BE）要等初始 SL 完成；成交时已带同等或更好 SL 算初始 SL 完成。
- 突破阶梯不被在途 SL 修改阻挡；多档可同时在途，`AvailableCloseVolume` 预留手数防超平；每档只发一次；部分成交只重试差额；成交按 deal ticket 去重；平仓和 SL 在 250ms 定时器按订单/成交历史对账。
- 「取消挂单」（v32.17 起）只撤未成交的突破挂单，已成交的突破持仓继续管理。
- 「立即结算」：先撤全部突破挂单，再平全部突破持仓（只平未预留手数），重试到清空。

## 交易适配
- 唯一发单出口 `OrderSendAsync`，每个请求登记 operation。
- `OnTradeTransaction` 的 `request/result` 只在 `TRADE_TRANSACTION_REQUEST` 有效且事件顺序不定：发送前暂存 operation↔position，request 事件回填 order，deal 先到就暂存待回放。SLTP 无 Deal，靠 request 事件确认。
- 返回码分四类，以 `AB_ClassifyTradeRetcode()` 为准：处理中 / 暂时性（可重试）/ 拒绝 / 未知（先查历史再重试）。发送失败打印 `AB_DIAG trade send failed`。
- 券商明确拒绝（INVALID、INVALID_PRICE、CLOSE_ONLY、LIMIT_* 等）按拒绝处理，不锁 EA；改 SL/TP 收到 NO_CHANGES 算完成。只有真正结果不明的才进未知锁。
- 改 SL/TP 全局限速：每秒最多 2 个；收到 TOO_MANY_REQUESTS 再暂停 1 秒。按钮触发的改 SL 不被挡（仍计入额度）；平仓、挂单、撤单不限速；Tester 里不限速。依据：实盘被限流的 178 次全是改 SL/TP。
- AutoTrading 按钮或 EA 的算法交易权限关着时，不发任何请求、不建记录；面板交易类按钮提示「自动交易未开启」；不加状态显示。
- Stop/Freeze Level 不够就等合法时机；同一操作最多一个在途，不在同一 tick 连发。
- 同一事件优先级：核对未知请求 → 突破结算 → 突破初始 SL/保本/阶梯/OCO → 组合取消清理 → 组合强平 → 热切换清理 → 组合 SL → 组合 TP → 手动平仓 → 普通保本/SL → 普通阶梯。高优先级已对某对象发单，本轮不再对它做低优先级动作（突破阶梯除外）。

## 账本、持久化与恢复
- 操作记录上限 128 条。满时先回收：失败且无成交的记录、已完成的改 SL/TP 记录；平仓、挂单、撤单和在途记录不回收。真满时在 EA 交互提示报一次（60 秒内不重复）并打印 `AB_DIAG operation ledger full`。
- 状态只存本终端 `MQL5\Files`，不用 `FILE_COMMON`（根因：旧共享账本里已结束的对象曾让恢复锁死交易）。
- A/B 轮换写入（版本、序号、校验），回读验证后才更新提交标记，另存对象快照。存在性用只读 `FileOpen` 判断，不用 `FileIsExist`（Tester 曾误报 5019）。
- 启动：读最新完整状态 → 账本核对清理 → 核对恢复证据（每个持久化仓位须在当前持仓或成交历史里找到）→ 登记新仓位。证据不通过就保持恢复锁、停止新的自动交易（日志 `AB_DIAG recovery remains locked`）；两份状态都坏同样锁住，不猜状态。
- 周期核对：启动一次 + 北京时间（UTC+8，不用券商时间）每小时 :00、:30。对象「无持仓且历史确认结束」连续两次确认后，才删除其普通/阶梯/操作记录；部分平仓余仓不删。
- 断线/重启后：阶梯、自动保本、未进入退出的组合 TP 只按恢复后真实报价判断，不补做已回撤机会；组合强平、取消/热切换清理、突破结算、OCO 持续恢复；无新报价不推测中间行情。
- 不持久化：图表选择、按钮效果、交互日志、未发出的手动平仓、面板运行时开关。

## 面板与图表（改 UI 前必读）
- 单个 Canvas，两页签「订单操作」「组合保本」，无设置页和输入框（参数在 EA 输入里改）。没被要求的 UI 项不动。
- 「EA 交互提示」只在组合保本页显示，内存环形缓冲（默认 7 条，1–20）。
- 字体：中文用系统 Noto Sans SC（400/600），数字英文用内嵌 Inter。必须先加载 EX5 的 TTF 资源，再按内部 family 名 `Inter`/`Inter SemiBold` 选，按资源路径选会悄悄回退。
- 刷新：`OnTick` 只标 dirty，250ms 定时器批量重绘，每批最多一次 `ChartRedraw()`；Canvas 只在尺寸变化时 `Resize()`（每 tick Resize 会闪烁）。
- 点 Canvas 对象后 MT5 会紧跟一次普通 `CHARTEVENT_CLICK`，必须去重，否则开关被翻两次。
- 图表：`普N/突N` 标签显示价格差（BUY = Bid − 开仓价，SELL = 开仓价 − Ask，按 Digits）；每个未管理持仓一个可点 `未管理` 标签（不显示 ticket）。

## 明确不支持
- 同账户同品种挂多个本 EA、管理范围重叠、其他 EA 或另一客户端同时改同一订单；后果由使用者承担，不做锁、心跳或冲突恢复。
- 导入 MT4 ticket/状态、跨券商接管；「发单后 0.2 秒内掉线重载」的极限窗口。
